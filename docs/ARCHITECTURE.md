# CaptionGrab Architecture

## Decision record

| # | Decision | Why | Alternatives rejected |
|---|---|---|---|
| 1 | Caption fetching moves server-side into a Cloudflare Worker | Browsers are CORS-blocked from YouTube's timedtext endpoints, and `captions.download` needs OAuth — a pure-frontend app **cannot** download captions, no matter the API key | Pure frontend with user API keys (proven broken); Vercel serverless functions (works, but splits the backend across two vendors and bills per GB-s) |
| 2 | Innertube player API instead of YouTube Data API v3 | Needs no key, no OAuth, no quota management; returns caption tracks + metadata in one call | Data API v3: requires OAuth for downloads and burns quota (200 units/download) |
| 3 | No database | Product state (history, settings) is personal and small — `localStorage` is simpler, free and more private | D1: justified only if accounts/sync are added later |
| 4 | No KV / Queues / Durable Objects | Nothing needs cross-request coordination; transcript fetches complete in <2s | Add KV only if abuse forces distributed rate-limiting |
| 5 | Same-origin `/api/*` via Vercel rewrite in production | Avoids CORS entirely, keeps one public origin, lets the Worker lock `ALLOWED_ORIGINS` | Direct `workers.dev` calls from the browser (fine too; `VITE_API_URL` supports it) |

## Request flows

### Resolve video + tracks — `GET /api/video?id=VIDEO_ID`

```
Client → (Vercel rewrite) → Worker
  1. Validate id (^[A-Za-z0-9_-]{11}$) → 400 INVALID_VIDEO_ID
  2. Edge-cache lookup (caches.default, 6h)
  3. Rate-limit check (30/min/IP default) → 429 RATE_LIMITED
  4. POST youtubei/v1/player (ANDROID client, WEB fallback)
  5. Map playabilityStatus → VIDEO_NOT_FOUND / PRIVATE_VIDEO / UNPLAYABLE_VIDEO
  6. Extract captionTracks → strip baseUrls (kept server-side)
  7. Cache + respond VideoInfo { title, author, thumbnails, tracks[] }
```

### Download transcript — `GET /api/transcript?id=…&lang=…`

```
Steps 1–5 as above, then:
  6. selectTrack(): exact lang → en → first manual → first auto
  7. If language differs and track is translatable, append &tlang=…
  8. Download baseUrl with fmt=json3 → srv3 → vtt fallback chain
  9. Parse + entity-decode into segments [{start, dur, text}]
  10. Cache (6h) + respond { segments, text, translated, isAutoGenerated, … }
```

Timeouts: 12s per upstream call; 30s client-side. Cache failures are non-fatal.

## Frontend structure

- `lib/youtube.ts` — platform detection + id extraction (watch/shorts/live/embed/music/attribution/bare-id). Pure, unit-tested.
- `lib/api.ts` — typed Worker client with timeout, typed `CaptionGrabError` codes and user-facing recovery copy (`describeError`).
- `lib/format.ts` — time formatting, SRT/VTT/TXT/JSON exporters, paragraphing, stats, download + clipboard helpers. Unit-tested.
- `components/Extractor.tsx` — 3-phase flow (paste → confirm/language → transcript) with skeletons and granular error states.
- `components/CaptionDisplay.tsx` — transcript studio: search, segments/reading tabs, click-to-seek player, export menu, stats.
- `hooks/useCaptionHistory.ts` — capped, de-duplicated, quota-safe `localStorage` history.
- `contexts/SettingsContext.tsx` — local preferences only. **No secrets.**

## Scaling notes (third-order analysis)

- **Traffic spike** → Worker autoscales; edge cache absorbs repeat videos; per-IP rate limit caps abuse. If abuse persists, add KV-backed global limiting.
- **YouTube changes Innertube** → single choke point (`fetchPlayerData`); the `fmt=` fallback chain and dual-client strategy absorb minor breakage. Monitor 502 rates.
- **History growth** → capped at 30 entries, stored per-device; no server cost.
- **Accounts/sync (future)** → add D1 + Workers OAuth at that point; current stateless design doesn't block it.
